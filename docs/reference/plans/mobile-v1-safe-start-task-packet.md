# 모바일 V1 안전 착수 작업 묶음

이 문서는 원본 저장소의 미추적 야간 작업 묶음을 현재 rebuild 구조에 맞게 정규화한 참고 실행계획이다. 작업 범위와 결정 상태는 [통합 개발 재계획](../../canonical/00-startio-dev-replan-v0.1.md), [모바일 V1 계약](../../canonical/product/09-mobile-v1-reset.md), [PRD](../../../.omx/plans/prd-startio-mobile-v1-reset.md), [테스트 명세](../../../.omx/plans/test-spec-startio-mobile-v1-reset.md)가 우선한다.

## 1. 목표와 완료 조건

되돌릴 수 있는 기반 하나를 만든다. 형식이 정해진 안전 경계, Expo 개발용 최소 뼈대, 얇은 공용 행동 계획 경계, 개인정보를 보호하는 로컬 이벤트·저장소 포트, 시험 가능한 시작 → 행동 계획 인계 지점까지 구현한다.

N0~N7의 증거가 있고 기존 `../startio` 웹 회귀 기준이 유지되며 운영 식별자·서명·스토어·최소 운영체제·원격 행동 데이터 값을 추정하지 않았을 때 완료한다. 전체 타이머·완료·EXP·실행 기록·사진 사용자 화면은 후속 작업이다.

## 2. 적용 계약

- React Native + Expo 개발 빌드 + TypeScript + Expo Router를 사용한다.
- 유효한 입력 뒤 필수 질문은 0개이며 정확히 3단계를 생성한다.
- `plan_allowed | safe_redirect` 안전 분류가 모든 대체 계획보다 먼저다.
- M21 해소 전 제한시간은 주입 가능하게 유지하고 8초를 임시 시험값으로만 사용한다.
- 타이머는 저장된 시각 기록을 기준으로 재계산한다.
- 체크 인증은 필수, 사진은 선택·로컬 전용, EXP 30은 `task_id + plan_id`마다 한 번이다.
- 로컬 이벤트가 기준 원천이며 원문 할 일, 생성 문구, 사진·경로, 이메일, 의료·자유 입력을 행동 분석에 포함하지 않는다.
- M25·M30 승인 전 원격 행동 데이터와 `install_scoped_id`를 구현하지 않는다.
- 주황색 중심 화면을 사용하지 않고 화면마다 핵심 동작 하나를 둔다.
- `../startio` 웹·API·SwiftUI는 삭제하거나 활성 사용자 화면 소스로 복사하지 않는다.

## 3. 구현 금지 범위

- 운영 EAS 인증정보, 서명, 실제 묶음·애플리케이션 식별자 추정
- 계정, 인증, 결제, 구독, 동기화, 캘린더, 푸시
- 서버 사진, 원격 행동 데이터, 원격 신고 서버
- 행동 계획·타이머 편집, 자유 입력 인증
- 최종 삽화·애니메이션·레벨 재설계·고급 보고서
- 광범위한 패키지 추출, 새 상태 관리 프레임워크, RAG·sLLM·기관·고급 개인화

Expo 뼈대에는 개발 빌드와 자료형 검사에 필요한 기준 의존성만 추가한다. 영속 저장소·사진 패키지는 Expo 호환성과 개인정보 영향을 기록한 뒤 선택한다.

## 4. 중단하고 담당자 결정이 필요한 사실

- Apple·Google 계정 담당자·유형·생성 시점·Play 시험 경로
- 묶음·애플리케이션 식별자와 법적 개발자·계약 명의
- EAS·서명·CI 인증정보 담당자
- 최소 운영체제와 실기기 시험 행렬
- 개인정보처리방침·지원 URL·심사·삭제 담당자
- 서명된 `release_window_sla`
- 원격 행동 데이터·삭제 URL과 운영 담당자
- M21 제한시간, M04/M35 재진입 타이머 의미, M16 실행 기록 KPI, M33 신고, M34 접근성, M42 디자인 토큰

## 5. 실행 순서

### N0 — 사전 점검

1. 현재 rebuild와 `../startio`의 Git 상태를 기록한다.
2. API, 도메인, 계약, 이벤트, 식별자, KPI, 저장 형식을 읽기 전용으로 목록화한다.
3. `../startio`에서 기존 회귀 명령을 실행하고 결과를 기록한다.
4. 겹치는 미설명 변경이나 기준 실패가 있으면 해당 경로를 확장하지 않는다.

### N1 — 안전 계약 우선

산출물:

- 플랫폼 중립 `plan_allowed | safe_redirect` 결과 결합·검증기·해석기
- `safe_redirect`를 보존하는 API·클라이언트 정규화
- 일반, 임상, 위기·자해, 위험·불법, 안전 입력의 잘못된 제공자 출력을 위한 합성 고정 시험 데이터

필수 검증:

- 모든 안전하지 않은 입력은 `do_not_chunk=true`, 계획 없음
- 안전하지 않은 입력이 타이머·인증·EXP·실행 장벽·할 일·계획·행동 이벤트를 0건 생성
- 안전 입력의 계약 위반 제공자 출력을 폐기하고 검증된 로컬 `plan_allowed`로 교체
- Metro 그래프에 서버·Node 전용 모듈이 없음

N1 통과 전 원격 행동 계획을 모바일 수직 기능에 통합하지 않는다.

### N2 — Expo 최소 뼈대

산출물:

- 루트 npm 작업공간과 Expo Router 기반 TypeScript 개발 빌드
- 운영 식별자·인증정보 없는 환경별 설정 형태
- 임시 중립·코발트 토큰을 쓰는 시작 화면 골격

증거:

- 모바일 자료형 검사·개발 묶음 생성
- 가능한 범위의 iOS·Android 기본 앱 실행
- 사용할 수 없는 실기기 증거는 공백으로 기록

### N3 — 얇은 행동 계획 어댑터

산출물:

- Metro 안전 행동 계획 결과 경계
- 주입 가능한 요청, 시계, 제한시간, 로컬 대체 계획
- `safe_redirect`를 잃지 않는 현재·목표 API 정규화
- 안전 분류 뒤에만 실행되는 결정론적 대체 계획

성공, 제한시간 초과, 오프라인, 4xx·5xx, 잘못된 구조·열거형, `safe_redirect`를 테스트한다. 광범위한 공용 패키지 추출은 하지 않는다.

### N4 — 시작 → 행동 계획 수직 기능

산출물:

- 2~240 문자소 묶음 검증과 입력 하나·CTA 하나
- 최초 원격 요청 전 AI 처리 동의, 거절 시 로컬 대체 계획
- 로딩·제한시간·대체 계획·오류·재시도·안전 안내 상태
- 1단계 강조, 2·3단계 보조, 실행 장벽 이름·편집이 없는 계획 화면
- `지금 시작` 타이머 인계 경계

검증:

- 필수 질문 0개
- 동의 전 원격 요청 0건
- `safe_redirect`에 계획·타이머 CTA 없음
- 390×844와 360×800에서 입력·CTA를 스크롤 없이 사용

### N5 — 로컬 이벤트 개인정보 경계

산출물:

- 로컬 기준 이벤트 계약과 안정 ID
- 금지 필드를 중첩 위치까지 기본 차단하는 개인정보 투영 테스트
- M25·M30 승인 전 원격 투영·동의·대기열·`install_scoped_id` 없음

`safe_redirect`는 할 일·계획·타이머·인증·EXP 행동 이벤트를 만들지 않는다. 원격 보관·삭제·전송 시험은 M25·M30 승인 뒤로 미룬다. 로컬 `clearAll` 검증은 필수다.

### N6 — 버전 있는 저장소 포트

산출물:

- 불러오기·원자적 교체·전체 삭제·손상·알 수 없는 버전의 계약
- 메모리 어댑터와 계약 테스트
- 최소 시작 → 행동 계획 복구

표현 가능한 로컬 상태는 할 일·계획·단계·타이머 시각·인증·사진 참조·기록·EXP·로컬 이벤트·AI 처리 동의다. 원격 식별자·대기열은 미리 예약하지 않는다. 구체 영속 저장·사진 패키지는 이 작업 묶음에서 설치하지 않는다.

### N7 — 통합 검증

1. `../startio` 회귀 명령과 rebuild의 새 대상 검사를 실행한다.
2. 모바일 자료형 검사·묶음 생성·계약 테스트를 실행한다.
3. 운영 식별자·비밀값·서버 전용 Metro 포함·금지 데이터·중복 열거형·P1/P2 코드가 없는지 검색한다.
4. 실패는 범위가 제한된 수정으로 해결하고, 미확정 결정이 필요하면 정확한 항목과 증거를 보고한다.

## 6. 출시 차단 조건

- 안전하지 않은 입력이 계획·대체 계획·타이머·인증·EXP·행동 이벤트를 생성
- `safe_redirect`가 로컬 `plan_allowed`로 변환
- 금지 데이터가 행동 분석·원격 투영에 포함
- Metro에 서버·Node 전용 모듈 포함
- 운영 식별자·서명·최소 운영체제·법무 URL·원격 통신 경로 추정
- 변경 때문에 `../startio` 회귀 기준 실패
- iOS·Android의 P0 의미가 달라짐

## 7. 보고 형식

```text
변경 요약:
- 완료한 N단계와 계약 결과

수정 파일:
- 정확한 경로

테스트 결과:
- 명령, 통과·실패, 핵심 증거

다음 작업:
- 다음 N단계 또는 담당자·사실이 필요한 정확한 MORE 항목
```

시뮬레이터, 건너뛴 명령, 사용할 수 없는 인증정보 검사는 통과 증거가 아니다.
