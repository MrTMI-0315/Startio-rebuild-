- 결정 상태: 승인
- 적용 범위: Startio Mobile V1 사용자 화면
- 시각 방향: 승인
- 정확한 색상 토큰: 검증 전 `provisional`
- 기능·안전·개인정보 계약: 변경 없음
- 상위 운영 계약: `AGENTS.md`

이 문서는 2026-07-23 내부 결정에 따라 Startio Mobile V1의 시각 방향을 갱신한다. 기존 문서와 충돌하는 시각 조항은 이 결정에 맞게 동기화하되, 기능·안전·개인정보 조항은 기존 canonical 계약을 그대로 따른다.

## 1. 결정

Startio의 사용자 화면을 기존 코발트 Primary 중심 시스템에서 **입력 우선의 파스텔 오렌지 중심 시스템**으로 전환한다.

첫 화면의 목표 반응은 다음과 같다.

> 뭔가 막히는 일을 한 번 입력해봐야겠다.

첫 화면에서는 즉시 작성 가능한 입력란이 가장 강한 요소가 되어야 한다. 주요 실행 버튼은 `첫 행동 만들기` 하나만 제공한다.

이 결정은 색상만 교체하는 작업이 아니다. 사용자가 서비스를 설명받기 전에 행동을 시작하도록 첫 화면의 위계·문구·간격·입력 경험을 함께 재설계하는 결정이다.

## 2. 기존 결정의 변경

다음 규칙은 현재 디자인 계약에서 제외한다.

- 코발트를 브랜드 및 Primary Action 색상으로 고정한다.
- 오렌지를 Warning 용도로만 제한한다.
- 모든 오렌지 중심 화면을 일괄적으로 금지한다.
- 기존 Startio 시안과 핵심 흐름 캡처를 긍정적 시각 기준으로 사용한다.

기존 오렌지 UI가 거부된 이유는 오렌지라는 색상 자체가 아니라 다음과 같은 표현 방식 때문이다.

- 채도가 높은 원색 오렌지
- 하나의 오렌지로 화면 전체 위계를 구성하는 방식
- 오렌지 그라디언트 또는 넓은 페이지 배경
- 카드와 대시보드가 과도하게 강조된 레거시 구성

따라서 이번 결정은 레거시 오렌지 UI로의 회귀를 허용하지 않는다. 허용하는 것은 접근성 및 사용성 근거를 갖춘 차분하고 적응형인 파스텔 오렌지 색상 체계다.

## 3. 유지하는 제품 계약

이번 결정은 다음 계약을 변경하지 않는다.

- 한 줄 할 일을 입력하면 정확히 3단계를 제공한다.
- 유효한 입력 뒤 필수 추가 질문을 하지 않는다.
- `plan_allowed | safe_redirect` 판단을 행동 계획보다 먼저 적용한다.
- 화면마다 핵심 실행 버튼은 하나만 둔다.
- iOS와 Android에서 P0의 의미를 동일하게 유지한다.
- 원문 할 일, 생성 문구, 사진·경로, 이메일, 의료·자유 입력 데이터는 행동 분석에 포함하지 않는다.
- 계정, 결제, 동기화, 캘린더, 푸시, 서버 사진, 고급 개인화 등 P1/P2 범위를 추가하지 않는다.

## 4. 새 시각 방향

새 디자인 시스템은 다음 특성을 가져야 한다.

- 입력란이 첫 화면에서 가장 강한 인터랙션이어야 한다.
- Primary Action은 따뜻하고 차분한 파스텔 오렌지 계열을 사용한다.
- 배경과 표면은 오렌지를 직접 넓게 칠하기보다 미세한 온도 차이와 중립색을 사용한다.
- 색상만으로 상태나 의미를 전달하지 않는다.
- 설명, 입력예시, 결과 약속 문구를 첫 화면에 중첩하지 않는다.
- 일반적인 AI 채팅 서비스가 아니라 막힌 일을 행동으로 전환하는 생산성 도구로 인식되어야 한다.
- 서체, 여백, 입력란, 상태 표현, 미세문구는 승인된 레퍼런스와 Apple 시스템 디자인 근거를 기록해야 한다.

## 5. 첫 화면 구성 원칙

첫 화면의 필수 구성은 다음과 같다.

1. 즉시 입력 가능한 할 일 입력란
2. `첫 행동 만들기` Primary Action
3. 입력과 행동을 방해하지 않는 최소한의 브랜드 식별 요소

다음 요소는 첫 화면에서 입력란과 경쟁하도록 배치하지 않는다.

- 여러 개의 입력예시
- 결과를 약속하는 홍보 문구
- 기능 목록 또는 온보딩 설명
- 복수의 주요 버튼
- 일반 채팅 전송으로 오해될 수 있는 버튼 문구
- 장식 목적의 대형 그래픽이나 카드 묶음

## 6. 레퍼런스 역할

각 레퍼런스는 지정된 역할 안에서만 사용한다.

| 레퍼런스 | 허용하는 역할 | 금지하는 해석 |
| --- | --- | --- |
| ChatGPT·Claude·Gemini | 즉시 입력 가능한 초기 화면 구조와 위계 | 일반 채팅 서비스의 정체성 또는 설명 문구 스택 복제 |
| Tiimo | 차분한 실행기능 지원과 접근성 | 전체 시각 체계의 모방 |
| Craft | 따뜻한 파스텔 표면과 재질 관계 | 행동 가치가 없는 장식적 재질 사용 |
| Focus by Meaningful Things (`focusapp.io`, 모바일 App Store ID `975017240`) | 진행 상태와 집중 상태의 표현 | 타이머 UI를 시작 화면에 그대로 도입 |
| Apple HIG 및 현행 Apple 디자인 리소스 | 서체, 여백, 입력 상태, 접근성, 적응형 화면의 품질 기준 | iOS 화면을 Android에 그대로 복제 |

Apple 디자인은 시스템 품질의 근거로 사용한다. Android에서는 동일한 P0 의미와 접근성 수준을 유지하면서 플랫폼 관례에 맞게 구현한다.

기존 Startio 4개 시안 및 핵심 흐름 캡처는 역사 자료 또는 금지 패턴 확인에만 사용하며, 새 디자인의 긍정적 근거로 사용하지 않는다.

## 7. 토큰 승인 정책

파스텔 오렌지 방향은 승인한다. 그러나 정확한 HEX 값은 이 문서에서 확정하지 않는다.

초기 색상 값은 모두 `candidate` 또는 `provisional`로 표시한다. 다음 검증을 모두 통과한 값만 `approved` 토큰으로 전환한다.

- Light Mode
- Dark Mode
- Increased Contrast
- Default·Focus·Pressed·Disabled·Selected 상태
- Error·Caution·Destructive 상태
- WCAG 2.2 AA 대비
- 색상 외 상태 구분 수단
- iOS와 Android에서의 의미적 일관성

최종 토큰 체계에는 최소한 다음 의미 역할이 존재해야 한다.

- Background
- Surface
- Text Primary·Secondary
- Border·Divider
- Focus
- Primary Action·Pressed·Disabled
- Selection
- Success
- Caution
- Destructive

## 8. 첫 화면 승인 기준

390×844와 360×800 화면에서 다음 조건을 만족해야 한다.

제작은 390×844 iOS에서 첫 화면의 위계·입력·키보드·Dynamic Type·VoiceOver를 먼저 교정하고, 같은 시제품·Expo 수직 기능 안에서 360×800 Android의 48dp·TalkBack·edge-to-edge·키보드 동등성을 통과하는 순서로 진행한다. Android 동등성 통과 전 다음 화면으로 넘어가지 않는다.

- 스크롤 없이 입력란과 `첫 행동 만들기`가 보인다.
- 입력란이 가장 먼저 인식되는 인터랙션이다.
- 주요 CTA는 하나만 존재한다.
- 입력예시, 결과 약속, 기능 설명이 입력란과 경쟁하지 않는다.
- 소프트웨어 키보드와 Safe Area가 적용되어도 입력란과 CTA가 사용 가능하다.
- 200% 텍스트 확대와 한국어 줄바꿈에서도 핵심 의미가 보존된다.
- VoiceOver와 TalkBack에서 입력란의 목적과 CTA의 의미가 명확하게 전달된다.
- 5명 중 최소 4명이 3초 안에 입력을 다음 행동으로 식별한다.
- 5명 중 최소 4명이 CTA를 일반 채팅 전송이 아니라 첫 행동 생성으로 이해한다.

## 9. 결정 근거 기록

활성 근거표는 `docs/reference/design/reference-evidence-matrix-2026-07-23.md`에서 관리한다.

색상, 서체, 여백, 입력란, 컴포넌트 상태, 미세문구를 결정할 때 다음 내용을 근거표에 기록한다.

1. 결정 대상
2. 참조한 레퍼런스
3. 해당 레퍼런스의 허용된 역할
4. Startio에 적용한 원칙
5. 그대로 복제하지 않은 요소
6. 접근성 및 사용성 검증 결과
7. `candidate | provisional | approved` 상태

근거가 없는 정확한 색상, 타입 스케일, 여백, radius, shadow, 입력 상태 및 미세문구는 최종값으로 승인하지 않는다.
