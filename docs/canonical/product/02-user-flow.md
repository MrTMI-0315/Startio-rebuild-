# Startio 사용자 흐름

## 1. 핵심 사용자 여정

Startio는 사용자가 해야 할 일이 있음을 인식했지만 시작하지 못하는 순간부터 개입한다.

```text
사용자가 할 일을 인식함
        ↓
진입 계기
- 사용자가 직접 앱을 엶
- 앱을 새로 실행할 때 완료하지 않은 할 일을 복구함
        ↓
01 앱 진입
- 할 일 직접 입력
- 사용자가 할 일을 입력한 뒤에만 선택적 코치 지원 제공
        ↓
02 첫 행동 생성
- 실행 장벽 분석
- 3단계 행동 분해
        ↓
03 즉시 실행
- 1단계 → 2단계 → 3단계 타이머
- Focus Mode(집중 모드)
- 선택지 최소화
        ↓
04 완료 인증과 재시작
- 필수 체크 인증 + 선택적 로컬 사진
- 할 일 단위 EXP(경험치) 1회 지급
- 실행 흔적 중심 History(실행 기록)
- 앱 안에서 계속하기·새 할 일 시작하기
```

## 2. 진입 경로

### P0 진입 경로

- 사용자가 직접 앱을 엶
- 사용자가 할 일을 직접 입력함
- 앱을 새로 실행해 진행 중인 할 일을 복구한 뒤 표시하는 계속하기 카드

### P1 진입 경로

- 오늘의 미션
- 푸시 알림 기본 틀

### P2 진입 경로

- 캘린더 알림
- 6주 프로그램 일정
- 기관 프로그램 미션

## 3. 필수 화면

P0에는 다음 화면이 필요하다.

1. 시작·할 일 입력
2. 행동 계획
3. 타이머·Focus Mode(집중 모드)
4. 완료 인증·완료
5. History(실행 기록)
6. 설정

## 4. 화면 명세

4.1절과 4.2절은 서로 다른 최상위 화면이 아니라 같은 시작 화면의 두 가지 상태를 설명한다.

## 4.1 시작·홈 상태

### 목적

사용자가 미루던 일을 바로 입력하여 시작할 수 있는 하나의 명확한 방법을 제공한다.

### 필수 UI(사용자 화면)

- 앱 제목·브랜드
- 진행 중인 할 일이 없을 때 표시하는 할 일 직접 입력란
- 하나의 핵심 CTA(실행 버튼): "바로 첫 행동 만들기"
- 이미 진행 중인 할 일이 있을 때만 표시하는 간결한 복귀 카드
- History(실행 기록)로 이동하는 내비게이션

### 핵심 행동

```text
할 일 입력
→ 실행 장벽 분석
→ 행동 계획
```

### 해야 할 것

- CTA(핵심 실행 버튼)를 시각적으로 가장 두드러지게 만든다.
- 화면을 단순하게 유지한다.
- 가장 관련 있는 미완료 할 일 하나만 보여준다.
- 행동으로 이어지지 않는 카드는 배치하지 않는다.

### 하지 말아야 할 것

- P0에 복잡한 대시보드를 표시하지 않는다.
- 지표를 지나치게 많이 표시하지 않는다.
- 사용자가 여러 모드 중 하나를 고르게 하지 않는다.
- 행동 계획을 생성하기 전에 코치와의 대화를 강요하지 않는다.

## 4.2 할 일 입력 상태

### 목적

사용자가 막힌 할 일을 입력란 하나에 적고 곧바로 첫 행동 계획으로 이동하게 한다.

### 필수 UI(사용자 화면)

- 큰 직접 입력란
- 예시 문구
- 제출 버튼
- 불러오는 중·분석 중 상태

### 예시 문구

```text
논문을 써야 하는데 막막해요.
방을 청소해야 하는데 계속 피하게 돼요.
공부를 시작해야 하는데 너무 벅차게 느껴져요.
```

### 핵심 행동

```text
할 일 제출
→ 실행 장벽 분석
→ 행동 계획
```

### 해야 할 것

- 한 번의 제출로 3단계 행동 계획을 생성한다.
- 예시는 입력을 돕는 바로가기로만 사용하고 대화 순환으로 만들지 않는다.

### 하지 말아야 할 것

- 행동 계획을 생성하기 전에 필수 대화 단계를 추가하지 않는다.
- 유효한 입력을 받은 뒤 추가 질문을 하지 않는다. 안전하지 않은 입력에는 질문 대신 안전 처리 결과를 반환한다.

## 4.3 행동 계획

### 목적

사용자가 즉시 실행할 수 있는 3단계 계획을 보여준다.

### 필수 UI(사용자 화면)

- 할 일 제목
- 짧은 코치 문구
- 펼쳐지고 가장 두드러지는 1단계, 그리고 보이지만 시각적으로 약하게 표시되는 2·3단계
- 단계별 타이머 시간
- 단계별 완료 조건
- 핵심 CTA(실행 버튼): "1단계 시작"

### 핵심 행동

```text
"1단계 시작" 누르기
→ 타이머·Focus Mode(집중 모드)
```

### 해야 할 것

- 1단계를 매우 작게 만든다.
- 타이머 시간을 명확하게 보여준다.
- 완료 조건을 구체적으로 만든다.
- 추론된 실행 장벽 enum(열거형)·유형은 사용자에게 표시하지 않는다.

### 하지 말아야 할 것

- 지나치게 많이 설명하지 않는다.
- 추상적인 조언을 제공하지 않는다.
- 시작하기 전에 사용자가 전체 행동 계획을 편집하게 하지 않는다.
- P0에서는 행동 계획이나 타이머 시간 편집을 허용하지 않는다.

## 4.4 타이머·Focus Mode(집중 모드)

### 목적

계획과 행동 사이의 지연을 없앤다.

### 필수 UI(사용자 화면)

- 현재 단계
- 남은 시간
- 코치 문구
- 완료 버튼
- 포기·일시정지 버튼
- 방해 요소를 최소화한 화면 구성

### 핵심 행동

```text
완료
→ 1단계 또는 2단계인 경우: 완료 상태를 저장하고 다음 단계를 제안함
→ 3단계인 경우: 완료 인증·완료 화면으로 이동함

포기
→ timer_abandoned(타이머 포기) 이벤트 기록
→ 홈 또는 재진입 안내로 이동
```

### 해야 할 것

- 화면을 차분하고 집중할 수 있게 유지한다.
- 완료 동작을 쉽게 만든다.
- 모든 타이머 이벤트를 기록한다.
- 1단계 → 2단계 → 3단계를 순서대로 실행하고 프로세스를 다시 실행한 뒤에도 현재 단계를 복구한다.

### 하지 말아야 할 것

- 소셜 피드를 추가하지 않는다.
- 복잡한 설정을 추가하지 않는다.
- 선택적 생산성 도구를 추가하지 않는다.

## 4.5 완료 인증·완료

### 목적

작은 성공을 눈에 보이게 만든다.

### 필수 UI(사용자 화면)

- 완료 문구
- 필수 체크 컨트롤과 선택적 로컬 사진 첨부
- EXP(경험치) 보상
- 다음 행동 제안
- 계속하기 또는 다른 할 일 시작하기 동작

### P0 완료 인증 유형

- 체크 인증
- 3단계 뒤 선택할 수 있는 로컬 사진 첨부. 사진은 필수가 아니며 업로드하지 않는다.

### P1 완료 인증 유형

- 텍스트 메모
- 서버에 동기화되는 사진 인증

### 핵심 행동

```text
완료 인증 제출
→ EXP(경험치) 지급
→ 완료 이벤트 저장
→ 홈으로 돌아가거나 계속 진행
```

## 4.6 History(실행 기록)·기본 보고서

### 목적

사용자가 행동했다는 증거가 쌓이고 있음을 보여준다.

### 필수 UI(사용자 화면)

- 최근 시작한 할 일과 완료 상태
- 완료한 단계 수와 완료 시각
- 완료 인증 상태·유형과 선택적 로컬 미리보기 이미지
- 최근 Start Latency(시작 지연시간)
- 전체 EXP(경험치)
- 해당 할 일에 지급한 EXP(경험치)

### P0 보고서

숫자 중심 대시보드보다 실행했다는 시각적 증거를 우선한다.

### P1 보고서

다음과 같은 종합 분석 정보를 추가한다.

- 가장 실행이 잘되는 시간대
- 중도 이탈 지점
- 복귀 횟수

## 5. 경로 초안

웹 MVP의 초기 경로 초안은 다음과 같다.

```text
/
  홈

/start
  할 일 입력·대화

/plan
  행동 계획

/timer
  타이머·Focus Mode(집중 모드)

/done
  완료 인증·완료

/history
  History(실행 기록)·기본 보고서
```

## 6. 흐름 보호 규칙

- 진행 중인 할 일이 없으면 `/plan`, `/timer`, `/done`은 `/`로 이동시켜야 한다.
- 사용자가 타이머를 포기하면 화면을 이동하기 전에 이벤트를 저장한다.
- 완료 인증이 제출되면 화면을 이동하기 전에 인증 내용과 EXP(경험치)를 저장한다.
- P0에서는 실제 사용자 인증을 도입하기 전까지 로컬 저장소나 모의 저장소를 사용할 수 있다.
