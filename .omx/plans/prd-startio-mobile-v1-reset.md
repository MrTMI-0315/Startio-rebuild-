# PRD — Startio Mobile V1 Reset

이 문서는 `../startio`의 로컬 OMX 계획을 현재 rebuild 저장소로 가져와 canonical 경로와 결정 상태에 맞게 정규화한 실행 보조 문서다. 제품 범위·일정·안전·데이터 결정은 [통합 개발 재계획](../../docs/canonical/00-startio-dev-replan-v0.1.md)과 [모바일 V1 계약](../../docs/canonical/product/09-mobile-v1-reset.md)이 우선하며 시각 방향과 토큰 승인 상태는 [2026-07-23 시각 결정](../../docs/canonical/product/10-visual-direction-2026-07-23.md)을 따른다.

## 1. 목표 결과

제품 담당자가 서명한 공동 공개 SLA 안에서 iOS와 Android에 상용 수준의 Startio P0 앱을 제공한다. 목표는 2026-10-12가 포함된 주간이며 10-19와 10-26이 포함된 주간을 예비 기간으로 둔다. 정확한 `release_window_sla`와 공개일은 `MORE(추가 결정 필요)`다.

새 사용자는 실행 장벽을 코치에게 설명하지 않고 한 줄 할 일을 입력해 정확히 세 행동을 받고, 세 개의 순차 타이머를 완료한 뒤 필수 체크와 선택적 로컬 사진으로 인증하고, EXP 30 한 번과 실행 흔적을 확인한다.

## 2. 성공 기준

1. 유효한 할 일 입력 뒤 필수 코칭 질문은 0개다.
2. 한 번의 제출과 최대 두 번의 누르기로 타이머에 도달한다.
3. iOS와 Android가 같은 P0 계약과 이벤트 의미를 구현한다.
4. 입력 우선의 파스텔 오렌지 방향과 레거시 원색·단색·배경형 오렌지 금지 기준을 사용자 5명으로 검증하고, 최소 4/5가 3초 안에 입력을 다음 행동으로 식별한다.
5. 안전한 할 일의 원격 계획이 실패하거나 주입된 제한시간을 넘으면 계약에 맞는 로컬 대체 계획으로 진행한다. M21 해소 전 8초는 제품 상수가 아닌 임시 시험 보호값이다.
6. 개인정보·스토어 공개 내용이 실제 SDK와 네트워크 흐름과 일치한다.
7. 공동 공개 전 양 스토어 후보가 승인되고 `release_window_sla`가 서명된다.

## 3. 사용자와 핵심 과업

핵심 사용자는 미루는 일을 알고 있지만 그 이유를 다시 분석하거나 설명하고 싶지 않은 사람이다.

> 할 일을 시작하기 어렵다고 느낄 때, 계속 계획하는 대신 행동할 수 있을 만큼 빠르게 첫 행동으로 바꾼다.

## 5. 비목표

기본 대화형 코칭, 자유 입력·서버 동기화 인증, 캘린더, 푸시, 계정, 결제, 구독, 클라우드 동기화, 전체 개인화, RAG·sLLM, 기관·B2B 기능, 의료·치료 주장은 제외한다. 선택적 로컬 전용 최종 사진만 P0에 포함한다.

## 6. 제품·디자인 요구사항

- 입력 우선 파스텔 오렌지 의미 방향을 사용하되 정확한 색상값은 적응형 화면·접근성·5인 시제품 통과 전 `candidate` 또는 `provisional`로 표시한다.
- 첫 화면은 즉시 작성 가능한 입력란이 가장 강한 상호작용이고 `첫 행동 만들기`가 유일한 주요 CTA다.
- 원색 오렌지, 단일 오렌지 위계, 넓은 오렌지 표면·그라데이션, 레거시 오렌지 카드·대시보드를 사용하지 않는다.
- 입력예시, 결과 약속, 기능 설명을 입력란과 경쟁하도록 쌓지 않는다.
- 실행 중 비핵심 내비게이션을 숨긴다.
- 1단계를 강조하고 2·3단계는 보이되 약하게 표시한다.
- 실행 장벽·범주 이름과 계획·타이머 편집을 P0에 노출하지 않는다.
- WCAG AA, iOS 44pt·Android 48dp, 동적 글자 크기, 화면 읽기 레이블, 색상 외 상태 표현을 적용한다.
- 최종 디자인 체계 구현 전 대표 사용자 5명 이상의 시제품 검증을 통과한다.

## 7. 기술 계획

### 결정

React Native + Expo 개발 빌드 + TypeScript로 하나의 모바일 제품 표면을 만든다. 기존 Next.js 행동 계획 API는 서버 경계로 유지하고, 수직 기능 구현에서 플랫폼 중립성이 증명된 TypeScript 로직만 선별 추출한다. SwiftUI는 P0 동등성 참고 자료다.

Expo Go를 출시 개발 환경으로 사용하지 않는다. 운영 묶음·애플리케이션 식별자, EAS 인증정보, CI 서명, 최소 운영체제는 담당자와 실제 값이 확인되기 전 추정하지 않는다.

제작은 화면 단위 iOS-first → Android parity로 진행한다. 390×844 iOS에서 한 화면을 먼저 교정하고 같은 Expo 수직 기능 안에서 360×800 Android 동등성을 통과해야 다음 화면으로 진행한다. 이는 전체 iOS 앱 선행, 별도 SwiftUI 제품, iOS 우선 출시를 허용하지 않는다.

### 구현 순서

1. `../startio`의 순수 로직, 부수 효과, API·이벤트·저장 형식을 목록화한다.
2. `plan_allowed | safe_redirect` 결과 결합과 안전 고정 시험 데이터를 먼저 고정한다.
3. 현재 rebuild 루트에 Expo Router 기반 최소 TypeScript 개발 빌드를 만든다.
4. 로컬 이벤트의 개인정보 기본 차단 투영과 버전 있는 저장소 포트를 계약 테스트로 고정한다.
5. 입력 → 행동 계획 → 타이머 인계의 각 화면을 iOS에서 먼저 교정하고 Android 동등성 gate를 순서대로 통과해 양 플랫폼 수직 기능 구현을 증명한다.
6. 증명된 순수 도메인·이벤트 코드만 공용 패키지로 추출한다.
7. 앱 수명 주기, 영속 저장, 순차 타이머, 완료 인증, 실행 기록, 접근성, 설정을 구현한다.
8. 공개 API에 요청 크기·빈도·악용·제한시간·관측 보호를 추가한다.
9. M25·M30 승인 뒤에만 원격 행동 데이터·삭제 경계를 추가하며 콘텐츠 신고는 별도 경계로 유지한다.
10. 실기기·베타·개인정보·스토어 통과 기준을 실행한다.

### 경계

- AI 공급자 인증정보는 서버에만 둔다.
- 원문 할 일은 행동 계획 요청에는 사용할 수 있지만 행동 분석에는 넣지 않는다.
- 타이머의 기준은 저장된 시각 기록이며 렌더링 틱만으로 상태를 판단하지 않는다.
- 보상과 이벤트는 중복 동작에도 멱등적이다.
- 플랫폼 전용 코드는 운영체제 통합에만 사용하고 제품 의미를 바꾸지 않는다.
- 로컬 이벤트가 실행 기록·KPI의 기준 원천이다.
- 원격 행동 데이터는 M25·M30 승인 전 비활성이며 `install_scoped_id`도 만들지 않는다.
- 사진과 경로는 앱 소유 로컬 저장소에만 있고 분석·신고·서버로 전송하지 않는다.
- `safe_redirect`는 타이머, 인증, EXP, 실행 장벽, 원문 행동 이벤트를 만들지 않는다.

## 9. 결정 기록

결정은 서버 행동 계획 경계를 유지하는 하나의 Expo·React Native 클라이언트다. 별도 SwiftUI·Kotlin 클라이언트, 웹 감싸기, iOS 우선 출시는 각각 중복 개발·수명 주기 품질·동시 출시 계약 때문에 채택하지 않는다.

실기기 수직 기능 구현과 한 번의 제한된 보완 스프린트 뒤에도 어느 한 플랫폼이 앱 수명 주기 정확성, 입력 준비성, 계획→타이머 성능을 충족하지 못하면 결정을 재검토한다. 그 전에는 공용 패키지 추출을 확대하지 않는다.

## 10. 주요 위험과 통제

- 일정: 날짜를 작업 목표로 취급하고 수직 기능 중단 기준을 적용한다.
- 스토어 계정: 계정 유형·생성일·베타 요건을 Sprint 0에 확인한다.
- AI 지연: 주입 가능한 제한시간, 요청 취소, 결정론적 대체 계획을 사용한다.
- 개인정보 불일치: 데이터 흐름 지도와 전송 내용 검사를 스토어 공개 전에 실행한다.
- 디자인 논쟁: 방향은 2026-07-23 시각 결정으로 고정하고 정확한 토큰은 적응형 화면·접근성·5인 시제품 증거로 판정한다.
- 범위 확장: 새 기능은 P0·출시 이후 표와 별도 결정 기록을 갱신해야 한다.

## 11. 구현 통과 조건

[모바일 V1 안전 착수 작업 묶음](../../docs/reference/plans/mobile-v1-safe-start-task-packet.md)의 `LOCKED(확정)` 범위는 시작할 수 있다. 운영 연결·출시 준비는 다음을 모두 충족한 뒤 진행한다.

- 본 PRD와 테스트 명세가 현재 canonical 계약 기준으로 다시 검토됨
- 우선 `MORE(추가 결정 필요)` 항목마다 담당자와 실제 값이 있음
- 개발자 계정 목록과 실기기 시험 행렬이 있음
- 저장·원격 행동 데이터·신고·동의·보관·삭제·백업·AI 제공자 데이터 흐름의 운영 담당자가 승인됨
- 운영 공개 전 제품 담당자가 `release_window_sla`에 서명함
- 첫 수직 기능 구현에 P1·P2 기능이 포함되지 않음

그 전에는 안전 계약, 운영 식별자 없는 Expo 뼈대, 얇은 계획 어댑터, 시작 → 행동 계획 수직 기능, 로컬 이벤트 개인정보 투영, 버전 있는 저장소 포트까지만 진행한다. 최종 디자인 체계는 사용자 5명 시제품 통과 후 구현한다.
