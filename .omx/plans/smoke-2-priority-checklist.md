## 판정 원칙

- `완료`: 현재 revision의 코드와 해당 항목에 필요한 자동·수동 증거로 확인했다.
- `실기기 확인`: 코드는 반영됐지만 물리 기기 증거가 없어 아직 통과하지 않았다.
- `교정 필요`: 기능은 동작하지만 사용자가 지적한 품질 기준에 미달한다.
- 사진은 선택 사항이다. 완료 직후 카메라를 강제로 열지 않는다.
- 사용자가 `사진으로 남기기`를 누르면 앨범 선택 화면을 거치지 않고 카메라를
  바로 연다. 앨범은 별도의 보조 동작으로 둔다.

P0 코드 누락은 현재 대조에서 발견되지 않았다. 다음 실기기 Smoke는 마지막
세 항목을 판정하는 검증 단계다.

## P1 — 흐름은 되지만 제품 감각을 떨어뜨리는 문제

1. 계획·완료·기록·설정 화면에서 카드와 외곽선을 기능적으로 필요한 곳에만
   남긴다.
2. 선택되지 않은 정보는 넓은 카드 대신 여백, 글자 위계, 얇은 구분선으로
   정리한다.
3. 입력 → 계획 → 타이머 → 완료 전환에 짧은 opacity·transform 움직임을
   사용하고 `동작 줄이기` 설정을 지킨다.
4. 사진 촬영 후 미리보기, 다시 찍기, 삭제의 관계를 한눈에 읽히게 만든다.
5. 완료 저장 전 화면과 저장 후 보상 화면의 역할을 더 명확히 구분해
   “완료를 두 번 확인한다”는 느낌을 줄인다.
6. 실행 기록의 반복 카드 밀도를 낮추고 핵심 시간값을 먼저 읽히게 한다.
7. 설정 화면의 긴 설명과 박스 묶음을 줄여 iOS 설정 화면처럼 빠르게
   훑을 수 있게 한다.

## P2 — 핵심 흐름 안정화 뒤 선택적으로 다듬을 문제

1. 단계 전환과 완료 보상의 세밀한 모션 리듬을 조정한다.
2. 기록이 많아졌을 때 기간별 요약과 탐색 방식을 검토한다.
3. 큰 글자·VoiceOver·고대비 조합별 시각 미세 조정을 확대한다.
4. 사진이 없는 완료와 사진이 있는 완료의 기록 표현을 더 세련되게
   차별화한다.
5. Android 동등성 검증 재개 시 같은 의미를 유지하면서 플랫폼 관례를
   교정한다.
