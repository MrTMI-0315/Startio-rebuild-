# Test Specification — Startio Mobile V1 Reset

이 문서는 `../startio`의 로컬 OMX 테스트 명세를 현재 rebuild 경로와 결정 상태에 맞게 정규화한 보조 시험 계획이다. 충돌 시 canonical 문서가 우선한다.

## 1. 검증 주장과 계층

출시 주장은 “지원하는 iOS와 Android 실기기에서 필수 코칭 대화 없이 동일하고, 개인정보를 보호하며, 앱 재진입에 견디는 P0 순환을 완료할 수 있고 양 스토어 후보가 공동 공개 준비를 마쳤다”이다.

검증 계층:

1. 순수 도메인·안전·계약 테스트
2. API 통합·개인정보 전송 내용 테스트
3. 모바일 구성요소·상태 기계 테스트
4. 양 플랫폼 전체 구간 테스트
5. 접근성·성능·앱 수명 주기·실기기 테스트
6. 베타 학습 통과 기준
7. 스토어 정책·공개 운영 절차 검사

스크린샷 하나나 정상 경로 시연만으로 완료를 판정하지 않는다.

## 2. 필수 시험 행렬

### A. 진입·계획·안전

| ID | 시나리오 | 기대 결과 |
| --- | --- | --- |
| A01 | 목표 iOS 화면에서 최초 실행 | 계정·초기 안내·스크롤 없이 입력과 CTA 사용 가능 |
| A02 | 목표 Android 화면에서 최초 실행 | A01과 같은 의미 |
| A03 | 유효한 한국어 할 일 제출 | 필수 추가 질문 0개, 로딩 뒤 정확히 3단계 계획 |
| A04 | 앞뒤 공백 제거 후 2 문자소 미만 | 네트워크 요청 없이 한 줄 안내, 입력 초점 유지 |
| A05 | 240·241 문자소 묶음 제출 | 240 허용, 241 로컬 거부, 화면 반응 유지 |
| A06 | 원격 계획 성공 | 정확히 3개의 순서 있는 단계, 안정 ID·행동·완료 조건, 1단계 15~20초 |
| A07 | M21 제한시간 초과 | 요청 취소 후 계약에 맞는 로컬 대체 계획, 한 번 누르기로 타이머 인계. M21 전에는 주입된 임시 8초 시험값 사용 |
| A08 | 안전과 무관한 4xx·5xx·오프라인·잘못된 응답 | A07과 같은 대체 계획; 기술 세부·원문 입력은 사용자 오류·원격 행동 데이터에 없음 |
| A09 | 사용자가 AI 처리를 거절 | 원격 요청 없이 로컬 대체 계획으로 진행 |
| A10 | 안전 고정 시험 데이터 | 일반 실용 할 일→`plan_allowed`; 임상 조언→`clinical_advice_request`; 위기·자해→`crisis_or_self_harm`; 위험·불법→`dangerous_or_illegal_request`; 안전 입력의 잘못된 제공자 출력→로컬 `plan_allowed`와 신고 동작 |

모든 `safe_redirect` 시험 데이터는 `do_not_chunk=true`, 계획 없음, 1~3개 지원 동작, 비어 있지 않은 안내 문구를 가져야 한다. 타이머·인증·EXP·실행 장벽·할 일·계획·행동 이벤트는 0건이어야 한다.

구현 시 `tests/fixtures/mobile-v1-safety.json`을 새로 만들며 최소 다음 합성 한국어 입력을 포함한다.

- 각 `reason_code`당 2개
- 의료와 인접하지만 안전한 실용 할 일 2개
- 안전한 입력에 잘못된 제공자 출력을 결합한 사례 2개

### B. 타이머·앱 수명 주기

| ID | 시나리오 | 기대 결과 |

| B08 | 1→2→3단계 완료 | 다음 순차 단계만 열리고 3단계 전에는 최종 인증이 잠김 |

상태 전이 기준:

| 현재 | 동작 | 다음 | 불변 조건 |
| --- | --- | --- | --- |
| `idle` | 시작 | `running` | 시작 시각과 이벤트를 카운트다운 전에 저장 |
| `running` | 일시정지 | `paused` | 누적 활성시간과 일시정지 이벤트 한 번 |
| `paused` | 재개 | `running` | 누적시간·타이머 ID 유지 |
| `running/paused` | 포기 | `abandoned` | 종료 상태, EXP 없음, 포기·재진입 상태 한 번 |
| `running/paused` | 완료 | `completed` | 현재 단계 종료, 다음 단계 또는 최종 인증 열기 |
| `abandoned/completed` | 타이머 동작 | 그대로 | 잘못된 중복 전이와 이벤트·보상 무시 |

백그라운드·재실행 재계산은 플랫폼이 제공하는 단조·절대 시각 기록을 사용하며 렌더링 틱만으로 시간을 줄이지 않는다. M04/M35 해소 전에는 경과시간 의미를 제품 상수로 고정하지 않는다.

## 3. 베타 실험

대표 참여자 최소 20명 중 최소 5명은 구현 전 시제품 시험에 포함한다. 원문 할 일 없이 시각 이벤트로 다음을 측정한다.

- 앱 실행 → 할 일 제출
- 제출 → 계획 표시
- 계획 표시 → 타이머 시작
- 타이머 시작 → 완료·포기
- 필수 추가 질문 수
- 대체 계획 진입·성공
- 플랫폼·앱 버전·시험 집단

출시 판단 목표:

- 대화 우선 iOS 기준선 대비 앱 실행 → 타이머 시작 중앙값 40% 이상 감소
- 5분 안의 유효한 제출 → 첫 타이머 시작 전환율 15%p 이상 개선
- 계획 수락 전 이탈 30% 이상 감소
- 90% 이상이 진행자 도움 없이 타이머 시작

신뢰할 수 있는 과거 기준선이 없으면 개선율을 만들지 않고 진행자 동반 비교 연구로 대체한다. 실패한 목표는 UX 재실험 또는 증거 공백·책임자·후속일을 기록한 제품 위험 예외 승인이 필요하다.

## 4. 지원 기기 통과 기준

Sprint 0에 최소 운영체제와 실제 기기를 지정한다. 최소한 다음을 포함한다.

- 최소 지원·현재 iPhone 각 1종
- 작은 화면·현재 Android 및 저성능 목표 기기
- 출시 후보 시점의 현재 iOS·Android
- 한국어, 큰 글자, VoiceOver, TalkBack, 지원하는 경우 밝기 테마

시뮬레이터만으로 앱 수명 주기, 접근성, 성능, 스토어 베타 통과를 판정하지 않는다.

## 5. 자동화와 증거

구현은 다음 명령 또는 동일한 CI 작업을 제공해야 한다.

- 도메인·안전·이벤트 계약 테스트
- API 스키마·제한시간·대체 계획·악용·개인정보 테스트
- 모바일 단위·구성요소·상태 기계 테스트
- 양 플랫폼 P0 전체 구간 테스트
- 접근성 자동 검사와 수동 화면 읽기 기록
- iOS·Android 출시 빌드
- 스토어 설명 정보·개인정보 점검표 검증

출시 후보별 보고서에는 앱 버전, 커밋, 기기·운영체제, 환경, 시각 기록, 결과, 담당자를 포함한다. 실행하지 못한 테스트는 통과가 아니라 출시 공백이다.

## 6. 종료 기준

### 시제품

- 대표 사용자 5명이 도움 없이 입력과 핵심 동작을 찾음
- 4/5 이상이 시각적 편안함을 5점 중 4점 이상 평가
- 진행을 막는 색상·명암·가독성 문제가 없음

### 수직 기능 구현

- 실기기 iOS·Android에서 입력 → 계획 → 타이머 인계 통과
- 각 화면의 390×844 iOS 교정 기록과 360×800 Android parity 기록이 쌍으로 존재하고 Android 통과 전 다음 화면으로 진행하지 않음
- 안전·대체 계획·행동 이벤트 개인정보 검사 통과
- 한 번의 보완 스프린트 뒤에도 수명 주기·성능이 실패하면 공용 패키지 추출 전에 Expo 결정을 재검토

### 베타

- 전체 P0 자동 시험 행렬 통과
- 접근성·수동 앱 수명 주기 행렬에 P0 차단 문제 없음
- 측정된 데이터 흐름에서 개인정보 공개 초안 작성
- 필요한 TestFlight·Play 시험 집단 활성화

### 출시 후보

- 동일 후보에서 도메인·API·모바일 전체 구간·빌드·개인정보 검사를 두 번 연속 통과
- 출시 차단·심각도 1·2 결함 0건
- 양 스토어 후보가 공개 전에 승인됨
- 공개·감시·지원·되돌리기·데이터 사고 담당자가 운영 절차 승인

## 7. 기존 저장소 회귀 기준

모바일 대체 구현이 인수 기준을 통과할 때까지 `../startio`에서 다음 기준을 보존한다.

```text
npm test
npm run test:p0-loop
npm run typecheck
npm run lint
npm run build
```

이 명령은 현재 rebuild 저장소의 검증 명령이 아니다. SwiftUI 역시 비교·기능 동등성 참고 자료일 뿐 목표 사용자 경험이 아니다.
