revision 0855a35부터 제품 revision 67019dc까지의 변경 중 CompletionScreen.tsx, PhotoProofPicker.tsx, mb19-product-language.test.mjs, micro-build 상단 상태, Thin Repository Loop 보고 규칙만 설명한다. 작업 시작 전부터 존재하던 Smoke 문서 변경과 Repository Loop 초안은 보존 대상으로 취급하며 이번 제품 구현의 결과로 과장하지 않는다.

Startio의 완료 흐름은 정확히 세 단계의 타이머가 모두 끝난 뒤 시작된다. 사용자는 선택적으로 사진을 붙이고 완료 기록을 저장한다. 저장 트랜잭션이 성공하면 같은 task와 plan에는 EXP 30이 한 번만 지급되고, 이후 성공 화면이 표시된다.

3단계 타이머 완료
→
완료 기록 전 화면
→
proof + EXP 원자적 저장
→
완료 성공 화면

기존 화면은 저장 전부터 “세 단계를 마쳤어요”라고 완료를 선언하고, 저장 뒤 다시 “완료했어요”라고 말해 두 번 확인하는 느낌을 만들었다. 사진 선택 면은 muted 배경과 외곽선을 동시에 사용해 정보 카드처럼 무거웠고, 완료 라우트 진입에는 전역 fade만 있어 화면 내용 자체의 짧은 방향성이 없었다.

핵심 직관

질문은 저장 전에, 성공 선언은 저장 뒤에

사용자가 세 단계를 실행했다는 사실과 그 실행을 Startio 기록으로 확정했다는 사실은 다르다. 저장 전 화면은 결정을 묻고, 저장 후 화면은 저장 결과와 보상을 알려야 한다.

상태이전 표현새 표현사용자에게 주는 의미
저장 전세 단계를 마쳤어요완료를 기록할까요?아직 되돌릴 수 있는 선택

그룹은 선의 개수가 아니라 의미 차이로 만든다

실행 시간은 얇은 위·아래 구분선으로, 사진 선택은 muted fill로, Primary Action은 파스텔 오렌지 면으로 구분한다. 사진 선택 영역에서는 배경만으로 충분한 affordance가 있으므로 외곽선을 제거해 CTA와 시간 정보가 더 먼저 읽히게 했다.

움직임은 의미를 보조하고 접근성 설정을 이기지 않는다

코드 워크스루

1. 완료 기록 전 상태만 애니메이션한다

CompletionScreen은 hydration, plan 존재, timer 완료, completion record 부재를 모두 확인한 뒤에만 저장 전 진입 모션을 시작한다. 저장 기록이 이미 있으면 기존 성공 모션 경로가 담당한다.

if (!isHydrated || !plan || timerState?.status !== 'completed' || completionRecord) {
  return;
}

if (tokens.reduceMotion) {
  checkOpacity.setValue(1);
  checkTranslateY.setValue(0);
  return;
}

이 가드는 잘못된 deep link나 hydration 이전 렌더링에서 애니메이션만 먼저 실행되는 일을 막는다. cleanup에서는 두 Animated value의 실행을 중단해 화면 이탈 뒤 콜백이 남지 않게 한다.

2. 같은 화면의 언어 역할을 바꾼다

<Text style={styles.eyebrow}>실행 기록</Text>
<Text accessibilityRole='header'>완료를 기록할까요?</Text>
<Text>실행 시간과 선택한 사진을 이 기기에 저장하고 EXP 30을 받아요.</Text>

CTA의 저장 의미와 헤더의 질문이 일치하며, 저장 뒤 화면의 “완료했어요”는 실제 completion record가 있을 때만 보인다. eyebrow를 같은 중심축에 놓아 왼쪽 label과 가운데 제목이 충돌하던 시각 위계도 정리했다.

3. 사진 선택 면에서 중복 외곽선을 제거한다

PhotoProofPicker의 비어 있는 선택 면과 선택 후 미리보기 면에서 borderWidth와 borderColor를 삭제했다. 배경색, radius, 여백, 아이콘과 텍스트 위계는 유지하므로 기능적 그룹과 44pt 이상 터치 의미는 바뀌지 않는다.

4. 제품 언어와 접근성 계약을 회귀 테스트로 고정한다

mb19-product-language.test.mjs는 새 질문 문구의 존재, 이전 중복 완료 문구의 부재, Animated.ScrollView와 tokens.reduceMotion 사용을 확인한다. 기존 카메라 직접 실행과 앨범 보조 동작 검증도 유지된다.

5. Thin Repository Loop에 보고서를 포함한다

repository-closed-loop-assets.md는 이제 모든 제품 작업 종료 시 현재 diff 또는 revision 범위를 명시한 self-contained $explain-diff HTML을 .omx/reports/에 만들고 README.md index와 완료 응답에서 링크하도록 요구한다. milestone에서는 같은 형식의 비교 범위만 넓혀 중복 보고서를 만들지 않는다.
