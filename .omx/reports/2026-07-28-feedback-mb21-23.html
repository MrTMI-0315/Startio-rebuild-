배경

비교 범위
기준 revision 34abc7a 이후의 MB-21 완료 시간 의미, MB-22 행동 문구 품질, MB-23 사진 선택성 변경과 그 테스트·상태 문서를 설명한다. 원시 timing 저장, 정확히 3단계, 안전 선판정, 멱등 EXP, local-only 사진 계약은 바꾸지 않았다.

Simulator 흐름 피드백에서 세 가지 의미 문제가 드러났다. 첫째, 완료 화면이 예정 시간보다 빨랐는지를 칭찬하면 사용자가 행동보다 타이머 종료를 목표로 삼을 수 있었다. 둘째, 일부 행동 문구는 생각·정리·준비처럼 완료 여부를 눈으로 판정하기 어렵거나 두 행동을 한 단계에 묶었다. 셋째, 사진이 선택 사항이라는 사실이 사진 동작보다 먼저 읽히지 않아 카메라 권한을 필수 절차처럼 오해할 수 있었다.

핵심 직관

측정값과 사용자 평가는 분리한다

savedMs와 overtimeMs는 제품 분석과 복구에 필요한 사실이다. 하지만 “예상보다 빨랐어요”는 사실을 보상으로 바꾼다. 화면은 5초 동안 실행했어요와 3단계를 모두 완료했어요만 말하고, 저장 구조는 그대로 둔다.

예이전 화면 해석새 화면 해석

120초 행동을 150초 실행30초 더 걸렸다는 부정 평가150초 실행했다는 사실

한 단계는 한 번에 판정 가능한 행동 하나다

좋은 문구는 대상, 수량 또는 종료 조건을 가진다. “정리해보기”보다 “같은 종류 물건 세 개 한곳에 모으기”가 낫고, “적고 보내기”처럼 두 동작을 묶은 원격 응답은 로컬 fallback으로 돌린다.

선택성은 권한 요청 전에 보여준다

사진 영역의 첫 줄은 사진 추가 · 선택 사항이고, 저장 안내는 사진 없이도 완료를 저장할 수 있어요다. 카메라 권한은 사용자가 사진 동작을 직접 눌렀을 때만 요청한다.

레퍼런스는 외형 템플릿이 아니라 판정 기준이다

Apple HIG는 이동·적시 권한·기본 관례, Things는 직접적인 다음 행동, Structured는 기록의 읽기 순서, Day One은 콘텐츠 우선과 사진의 보조 역할만 참고한다. 색상·카드·내비게이션 외형은 복제하지 않으며 Startio canonical 계약이 항상 우선한다.

코드 흐름

1. 완료와 기록에서 속도 평가를 제거한다

CompletionScreen은 계획 시간 합과 variance 계산을 더 이상 화면 문구에 사용하지 않는다. HistoryScreen도 저장·초과 평가를 붙이지 않고 실제 실행 시간만 표시한다.

<Text>{formatDuration(actualMs)} 동안 실행했어요</Text>
<Text>3단계를 모두 완료했어요</Text>

스토리지 모델과 completion transaction은 수정하지 않았기 때문에 기존 archive와 EXP 멱등성은 그대로다.

2. fallback을 구체화하고 원격 결과에 같은 경계를 적용한다

fallback.ts는 “시작할 시각 하나 적기”, “핵심 한 줄 보내기”, “물건 세 개 한곳에 모으기”처럼 한 번에 판정 가능한 행동으로 교체됐다. remotePlan.ts의 isConcreteAction은 44자 경계, 추상 패턴, 한국어·영어 복합 행동 패턴을 검사한다.

function isConcreteAction(value: unknown): value is string {
  if (!isBoundedText(value, 44)) return false;
  const action = value.replace(/\s+/g, ' ').trim();
  return !ABSTRACT_ACTION_PATTERNS.some((pattern) => pattern.test(action))
    && !BUNDLED_ACTION_PATTERNS.some((pattern) => pattern.test(action));
}

검사에 실패한 원격 응답은 부분 채택하지 않고 기존 로컬 계획으로 돌아간다. 안전하지 않은 입력을 계획으로 바꾸는 경로는 추가되지 않았다.

3. 사진과 EXP의 역할을 저장 전후로 나눈다

PhotoProofPicker는 영역 제목과 선택 사항을 추가했다. CompletionScreen의 저장 전 설명과 접근성 hint는 사진 없이 저장할 수 있음을 말한다. 저장 전 EXP 문구는 제거하고, EXP는 completion record가 생긴 뒤 성공 화면에서만 결과로 표시한다.

→

4. 회귀 테스트와 Thin Repository Loop를 갱신한다

mb01-coaching.test.mjs는 여덟 범주의 3개 행동이 짧고 단일하며 서로 다른지 확인한다. mb08-remote-plan.test.mjs는 추상·복합 원격 행동이 fallback으로 돌아가는지 확인한다. mb19-product-language.test.mjs는 속도 평가 부재, 사진 선택 라벨, 적시 권한 경로, 저장 전 EXP 부재를 고정한다.

micro-build 계획에는 MB-21~26과 레퍼런스 적용 규칙을 추가했다. 다음 순서는 이 변경을 push한 뒤 물리 iPhone Smoke를 먼저 수행하고, 문제가 없을 때 MB-24 화면 이동 문법으로 넘어가는 것이다.
