Background

기존 타이머는 중앙 숫자가 남은 시간을 보여주지만 48개 눈금은 진행률처럼 채워져, 같은 원 안에서 두 요소가 반대 방향의 의미로 읽힐 수 있었다. MB-24는 시간 정책이나 상태 머신을 건드리지 않고 표시 계층만 교정한다.

고정 계약
15초·60초·120초 duration, timestamp 복구, timer event 이름과 발생 조건, proof 접근 조건, EXP 지급 조건은 변경하지 않았다.

Core intuition

숫자와 눈금은 모두 같은 질문에 답한다: “얼마나 남았나?” 시간이 흐르면 숫자는 줄고 주황색 눈금도 시계 방향으로 사라진다.

시작
100% · 24 segments
→
진행
50% · 12 segments
→
종료
0% · 0 segments

단계 정보는 “1 / 3” 숫자 경쟁 대신 얇은 3구간 표시로 낮췄고, CTA는 현재 상태에서 사용자가 할 수 있는 행동을 직접 말한다.

Code walkthrough

1. 표시 계산을 순수 함수로 분리

getElapsedSegmentCount(progress)
getRemainingPercent(progress)
formatTimerStartLabel(seconds)

진행률 clamp, 24구간 변환, 접근성용 남은 비율, 15초·1분·2분 CTA 문구가 렌더 코드 밖에서 결정된다.

2. 타이머 화면의 의미 통일

TimerDial은 경과 구간을 중립색으로 바꾸고 남은 구간만 주황색으로 유지한다. 초과 상태는 추가 색 효과 없이 +0:12와 얇은 적색 테두리만 남긴다.

3. 상태 위계 정리

시작 전 CTA는 실제 시간을 말하고, 실행 중 primary CTA는 끝냈어요다. 일시정지는 secondary text action으로 유지되며 완료 조건은 원 가까이 한 줄로 배치된다.

4. 계획 문서 동기화

실행 계획을 새 우선순위 MB-24, MB-25A/B/C, MB-26, MB-27로 갱신하고 각 MB의 별도 commit·push·HTML 보고서 loop를 명시했다.
