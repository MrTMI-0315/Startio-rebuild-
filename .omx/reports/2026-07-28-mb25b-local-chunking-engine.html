Background

기존 로컬 coaching은 TaskCategory별 세 문장을 바로 고르는 selector였다. v0.2는 안전 분류 뒤 실행 장벽을 제한된 규칙으로 분류하고, 2~3개의 후보를 Gate와 고정 점수로 비교한다.

결정론
같은 정규화 입력과 같은 policy version은 같은 장벽, 후보, Gate 결과, score, 선택 전략을 반환한다. taskId와 planId는 세션 식별을 위해 기존처럼 생성된다.

후보는 category profile의 행동 문구와 BarrierType별 primitive 조합으로 만들어진다. 모든 후보의 시간은 CONTACT 15초, NARROW 60초, PRODUCE 120초로 고정된다.

Code walkthrough

1. 제한 신호와 장벽 분류

extractLimitedTaskSignals는 TaskCategory, target kind, 장벽 cue 개수만 만든다. classifyBarrier는 completion pressure, choice, sequence, overwhelm, activation cue를 고정 우선순위로 판정한다.

2. 후보 생성과 Gate

category별 CONTACT/NARROW/PRODUCE copy profile과 scope-first, restore-then-make, choose-then-make, mark-continuation primitive 조합으로 2~3개 후보를 만든다. 모호한 단독 동사, 묶인 행동, 관찰 불가능한 완료, 역할 오류, 중복, 위험한 어조는 ranking 전에 탈락한다.

3. 고정 점수와 fallback

Gate 통과 후보만 100점 기준과 penalty로 평가한다. low confidence나 70점 미만은 기존 general + unknown fallback으로 간다. 동점은 생성 순서를 유지한다.

4. Policy 경계

createLocalPlan 기본값은 v0.2이며 명시적 local_chunking_policy_v0.1 호환 경계가 남아 있다. 원격 요청, 동의, timeout, validator는 그대로이고 원격 실패 뒤 로컬 fallback만 동일한 v0.2 엔진을 사용한다.

5. Privacy-safe debug

결정 descriptor는 policy, barrier, confidence, candidate count, selected strategy, primitives, fallback 여부만 가진다. raw input은 descriptor와 behavior event에 들어가지 않는다.
